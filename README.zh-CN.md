# Cognition-Gated Development

**认知门控开发工作流** — 一套以**开发者主权**为核心的 AI 辅助开发流程。

```
[模糊需求]
     ↓
[云端架构师] ──→ COGNITION.md (架构规划)
     ↓
[人类审查] ──→ 冻结
     ↓
[本地路由器] ──→ DISPATCH.md (任务调度)
     ↓
[人类审查] ──→ 批准
     ↓
[执行器] ──→ 生产代码
```

## 核心理念

当前 AI 编程工具（Cursor、Trae Solo 等）的默认模式是"AI 全自动改代码"，这在几次对话后就会让项目变成只有 AI 自己看得懂的黑盒，开发者丧失架构控制权。

这套流程用一个**文档驱动的串行状态机**来解决这个问题：每一层都有强制的人类审查锁，让你始终掌控项目方向。

**核心信念**：AI 应该是你的智力放大器，而不是你理解自己代码的替代品。

## 快速开始（3 个文件）

复制以下 3 个文件到任何项目的根目录即可开始：

| 文件 | 角色 |
| :--- | :--- |
| `.trae/skills/cognition-architect/SKILL.md` | 云端架构师 — 将模糊需求转化为像素级实施文档 `COGNITION.md` |
| `.trae/skills/local-router/SKILL.md` | 本地路由器 — 将规划拆解为可执行的原子任务 `DISPATCH.md` |
| `.ai_rules` | 权限边界声明 |

不需要本地模型、不需要特定硬件、不需要安装任何依赖。整个流程在你的现有 AI 平台上通过 Skill 指令约束运行。

## 完整流程（7 步）

1. **提出需求** — `@cognition-architect 我想做一个 ...`
2. **审查规划** — 阅读生成的 `docs/plans/COGNITION.md`
3. **调用路由器** — `@local-router COGNITION.md 已冻结，请拆解调度`
4. **审查调度** — 阅读生成的 `docs/dispatch/DISPATCH.md`
5. **执行** — 批准后按调度逐个完成任务
6. **错误处理** — 分层修复：执行器自愈 → 路由器修复 → 云端查询 → 你终审
7. **验证** — 确认产出符合规划

## 示例

`examples/tetris/` 目录包含一个完整的运行示例——一个像素风格俄罗斯方块游戏，从架构规划、调度拆解到最终代码，全部通过这套流程完成。
